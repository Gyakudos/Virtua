# Virtua `000.015.004.2026` (pre-release)

Tag format: `Major.Minor.Sub.Year` → `000.015.004.2026` (Major.Minor.Sub.Year = 000.015.004.2026).

Build: `000.015.004.2026` (same as the GitHub release tag; the old `0.010.24.11.26` desktop-only string is retired).

Android version: `000.015.004.2026` · version code `15004`.

## Highlights

- **GGUF model sync fix:** model discovery now reads the local Ollama manifest files directly, so installed models sync even when the Ollama daemon is not running or `/api/tags` is unavailable.
- **Phone mode sync fix:** **Portable Sync → Pull from PC / Push to PC / Trusted Devices** now use the paired desktop bridge in Phone mode too. Previously they fell back to the local SAF bundle API, so models never transferred and the Pull button stayed disabled after switching to Phone mode.
- GGUF transfers buffer network reads into ~1 MB writes, so multi-GB models need far fewer Android bridge calls. Sync messages now report concrete model errors instead of silently showing zero models.
- Desktop build display now uses the GitHub tag format (`000.015.004.2026`) instead of the old date-based `0.010.19.11.26` string.
- **Port** on PC and **Portable Sync** on Android:
  - PC **Port** panel has **Pair New** (fresh QR with a rotated local token), **Sync** (send the current PC snapshot to the connected phone), and a **Trusted Devices** list with revoke/re-allow.
  - Android has a Portable Sync tab with a local QR scanner, manual entry, pull/push, and the same trusted-device view.
  - Still opt-in, LAN/mDNS/Tailscale only; no cloud relay.
- Manual GitHub update check in **Data → system**; GitHub is contacted only after clicking **Check for update**.
- Local-first Android companion:
  - Phone mode runs GGUF models on-device with `llama-android` and keeps chats/characters/settings/avatars app-private.
  - Desktop link mode connects over LAN/mDNS/Tailscale with a pairing token; no cloud relay.
  - SAF import/export for backups and user-provided VRM avatars.
- GGUF model sync: **Port → Sync** and phone **Pull from PC** discover installed Ollama models and stream their GGUF blobs directly from the PC bridge into the phone’s app-private `filesDir/models`. Large models are streamed in chunks instead of being embedded in the JSON snapshot, and models already present at the same size are skipped.
- Transactional desktop restore and Android bundle export with copied `.vrm` files; no avatar or model is bundled in the APK.
- Signed Android release APK/AAB use relative embedded web-asset paths, so the WebView UI boots from `file:///android_asset/public/index.html` without a white screen.
- Android uses a dedicated phone-first chat UI instead of the desktop layout: large readable message bubbles, 16px text, 48px touch targets, a fixed composer, bottom tabs, and bottom sheets for chats, characters/personas, models, and setup.
- Android avatar: a compact live 3D VRM preview sits above the chat, with a CSS 2D sprite fallback when no VRM is selected or WebGL is unavailable. VRM files selected on the phone or delivered by a PC **Port → Sync** are saved app-private and reload after restart.

## Release assets

- `Virtua-Setup-0.10.0-x64.exe` — Windows x64 NSIS setup (per-user install, desktop and Start menu shortcuts). It is unsigned, so Windows SmartScreen may ask you to choose **More info → Run anyway**.
- `app-release.apk` — signed arm64-v8a release APK for the local-first companion, including the local QR scanner (camera permission used only when you tap **Scan PC QR**). Install with `adb install -r app-release.apk` or open it on the phone.
- `app-release.aab` — signed Android App Bundle for Play/store upload; the APK above is the direct-install build.

Both assets are local-only builds. No VRM, GGUF model, user database, cloud key, or telemetry is bundled.

## Privacy

No telemetry, no cloud APIs, no runtime network calls by default. The only outbound requests are the manual update check and the opt-in local/Tailscale phone bridge.

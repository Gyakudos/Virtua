## Highlights

- **No GGUF is bundled into the APK.** The default `qwen2.5:3b-instruct` model is about 1.9 GB; embedding it would make the APK/AAB unusable, break store limits, and violate the local-first rule that no user model is shipped inside the app. Models stay on the PC and are copied only over the opt-in local bridge.
- **Download Model From PC now shows live progress** while a large GGUF streams from the desktop, instead of looking stuck during a multi-GB transfer. The progress bar and `Downloading <model>… NN%` label sit directly under the download button.
- **Post-download verification:** after the transfer, the phone immediately re-reads its native model list and the message reports `Phone models: N [names]`. If it still says zero, that is now an explicit diagnostic rather than a silent failure.
- **Auto-refresh:** the chat model sheet and the Setup model list refresh automatically when a model arrives; no manual **Refresh models** tap is required.
- Includes the `000.015.006` direct-download action: **Portable Sync → Download Model From PC → List models on PC → choose model → Download Model From PC**.
- If the PC list is empty, the message includes the Ollama root, manifest count, and discovered model names.
- GGUF transfers buffer network reads into ~1 MB writes and skip models already present at the same size.
- **Portable Sync** in Phone mode uses the paired desktop bridge for pull/push/trusted devices; no cloud relay.
- Signed arm64-v8a release APK/AAB with relative embedded web assets; no VRM, GGUF, user database, keystore, or telemetry is bundled.

## Privacy

No telemetry, no cloud APIs, no runtime network calls by default. The only outbound requests are the manual update check and the opt-in local/Tailscale phone bridge.
